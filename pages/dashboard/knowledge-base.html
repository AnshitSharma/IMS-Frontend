01Getting Started

Signing in

Enter your username and password. Tick Remember me only on your own machine — it keeps you signed in between browser sessions. On a shared workstation leave it unticked.

A sign-in lasts 24 hours

After that you are returned to the login screen. Closing the browser also ends the session's ability to renew itself quietly, even with Remember me ticked — so a tab left open overnight will usually ask you to sign in again in the morning. Save long forms as you go rather than leaving them open.

Forgotten password

Use the reset link on the login screen. You will be emailed a single-use link to set a new password. An administrator can also reset it for you from Access Control — in that case nothing is emailed, they hand you the new password directly, and you are signed out of every device.

What you can see, and what you can do

The system shows you what your role allows, but it no longer simply hides the work. New accounts start on the Viewer role, which can see everything and change nothing directly. Rather than greying out Add Component and Build Server, the system leaves those buttons in place and turns them into Requests: you fill in the same form, and it goes for approval instead of being written straight away.

Which pages are genuinely restricted

Rack View and Settings → Request Types are administrator-only. Everything else — including Requests — is on every signed-in user's sidebar. If a button carries the tooltip "You will be asked to submit this as a request for approval", that is not a fault; it is the normal route for your role.

02The Dashboard

The dashboard answers one question: what do we have, and how much of it is free? Each hardware type gets a tile showing total, available, in use, and failed. The sidebar repeats those totals as counters, so you can watch stock without leaving the page you are on.

Below the tiles, a recent activity strip shows the latest changes across the system — components added, components removed from servers, roles changed.

Reading the numbers

Available is in stock and free to assign. In use is installed in a server. Failed is marked faulty and excluded when building. The three always add up to the total.

Compute Platforms has no tile yet

The twelfth hardware type has a sidebar counter but not yet a dashboard tile. For its totals, open the Compute Platforms page itself.

03Locations

Locations lists every site the company holds hardware at — name, description, address, coordinates and notes. It is the newest page in the system and the one most other pages now depend on.

Locations feed every other form

The Location dropdown on component forms, server forms and rack forms is loaded from this page. The old hardcoded list of sites is gone. If a site is missing here, nothing can be filed against it anywhere else — add it here first.

What a location shows

The Objects column carries chips counting the racks, servers and components held at that site. Click a location's name to expand the racks it contains, each showing used and free U, its server count and its floor; administrators can jump straight into Rack View from there.

Retiring and deleting

A site that is no longer in use should be switched off with the In service toggle rather than deleted — that keeps its history intact. If you do delete a site that still holds hardware, the system does not refuse: it opens a Move everything to dialog and asks which site should take the contents. Deleting an empty site just asks you to confirm.

Saving a location cascades

Changing a site re-stamps the records held there, and tells you how many: "Location saved · re-stamped 4 server(s) and 37 component(s)". Editing a rack's location does the same for everything in the rack. You never update those records one by one.

04Managing Inventory

Twelve kinds of hardware are tracked, each with its own page:

PageWhat it holds
CPUsProcessors. The socket type drives most compatibility rules.
RAMMemory modules, with ECC and registered distinctions.
StorageDrives of all form factors — 2.5-inch, 3.5-inch, M.2, U.2.
MotherboardsSystem boards. Define socket, memory slots, and PCIe layout.
Network CardsNICs, including their port types.

Adding a component

1
Pick the model

Cascading dropdowns narrow from brand, to series, to model. You are choosing from the hardware catalogue, not typing freehand.

2
Identify the physical unit

Enter the serial number — required for Storage and SFP, optional but strongly advised elsewhere. An asset tag is generated for you, and the confirmation names it: "Added as BDC-CPU-000128 — label the unit with this tag."

3
Say where it is

Location is required and comes from the Locations page. Use Store / Shelf for where loose stock physically sits — Shelf B3, Bin 12. Rack Position is read-only: it fills itself in when the unit is installed in a server that is racked.

4
Add dates and notes

Purchase, installation, and warranty-end dates are optional but make warranty reporting useful.

The model must exist in the catalogue

Every component is checked against the catalogue before saving. If your model is not in the dropdowns it must be added there first. Do not pick the nearest match — compatibility checking would then run against the wrong specification.

Finding things

Every inventory page carries a search box, a status filter and a location filter. The location filter searches the whole inventory for that site, not just the rows currently on screen.

Editing, deleting, and bulk actions

Rows show Edit and Delete only if your role includes them. Several rows can be selected for a bulk status update or bulk delete — useful when a shipment arrives or a batch is retired. Add Component is shown to everyone; without create permission it raises a Request instead of writing the record, and the same is true of the edit form.

A unit installed in a server cannot be deleted

The delete is refused and names the culprit: "This cpu is installed in server configuration(s) … Remove it from the configuration before deleting it." In a bulk delete the rest of the batch still goes through and the blocked rows are listed individually. If the system cannot establish one way or the other whether a unit is in use, it refuses rather than guessing.

05Building a Server

The Server Builder assembles a configuration from units already in inventory, checking at each step that the parts fit together. There are two ways to start: install a compute platform — a whole box we stock — or build up from a bare motherboard.

1
Start the configuration

Name it, and enter the serial number printed on the box. That is the manufacturer's serial, not a tag the system invents, and it is required for a real server; virtual and bench builds are exempt. A serial already on file is refused by name: "Serial number 'X' is already recorded against the server 'Y'." Set the location, and if it is going straight into a rack, its U height.

2
Install a platform, or choose the motherboard first

With a platform, the board and chassis arrive with it. Building up instead, pick the motherboard first — nearly every later rule derives from the board, and picking it first lets the builder filter everything else for you.

3
Add components, guided by the fit lists

For each type the builder shows what fits and what does not, with a reason on every entry — and separates parts that fit and are in stock from those already in use elsewhere.

4
Validate

Validation lists missing required components and shows how much of each resource you have consumed.

5
Finalise and place it

A finalised configuration can be assigned to a rack at a U position, or into a bay in a blade enclosure.

Compute platforms

A compute platform is a whole server box held in stock as a unit. Pick the platform, then its version — the version is the SKU we actually hold on the shelf. Its motherboard and chassis come with the box and are never stocked separately, so you will not find them on the Motherboards or Chassis pages as loose parts.

Versions you cannot pick are still listed, with the reason why — usually that the box, or a card that ships with it, is not in stock. Parts that are bolted in at the factory are never stock-checked and never make a version unselectable.

Changing or removing a platform releases the whole build

Both Change and Remove free every component currently installed back to available stock. The system refuses the first attempt and re-asks, listing exactly what would be released. Slots the platform supplies carry a locked Compute platform badge — you cannot remove that board or chassis on its own unless a separately stocked twin of the same model exists. Neither is possible at all once the server is finalized.

Six components are required

A configuration is not complete until it has all of: chassis, motherboard, CPU, RAM, storage, and a network card. Whatever is absent is named in one line — Missing required component(s): chassis, nic. This is checked when you validate or finalise, never while you are still adding parts.

The resource budget

Validation shows where you stand against the board's limits. A single-socket board with a 128-lane CPU reports something like:

ResourceMaxUsedFree
CPU sockets110
Memory slots808
Memory capacity (GB)204802048
PCIe lanes1280128
PCIe slots ×16505

PCIe lanes are attributed to their source, so you can see the budget comes from the CPU rather than the board. There is no longer an overall compatibility score — a build is described by the rules it passes and fails, not by a number.

Editing and moving a finished server

Each server card carries an Edit button for its name, description, serial number and location, and a separate panel for changing its status. That panel lists only the moves your role can actually make, marks the ones that need the build validated first, and takes an optional reason. Below it is the server's movement history, including Request #NN where a move came from an approved Request. Administrators also get a Move server button for rack placement.

Finalising is no longer a one-way door

A server finalized by mistake can be sent back to Building, given the permission for it. Note also that working on a build's parts and editing the build's own details are separate permissions — you may well be able to add a CPU to a server you cannot rename.

Trying things out safely

The Server Compatibility page is a bench for experimenting. Builds made there are sandboxes and never reserve real stock, so you can test a combination without taking parts out of circulation. A bench build may even hold hardware we do not own — only the model has to exist in the catalogue.

Sandbox builds are kept separate

A sandbox build does not appear in the ordinary server list — it belongs to the Server Compatibility bench, and it is kept out of the template picker too. It also cannot be finalized: "This is a compatibility bench build and cannot be finalized… rebuild it as a real server to deploy it." If a test build seems to have vanished, that is why; it has not been deleted.

06Understanding Compatibility

Every check returns findings in three buckets. Which bucket you are looking at tells you what to do next.

Issues

Hard stops. The combination will not work and cannot be saved.

Warnings

It will work, but something is compromised or unnecessary.

Recommendations

How to resolve it — often naming the parts that would fit.

Issues you will actually meet

MessageWhat it means
CPU socket LGA3647 incompatible with motherboard socket SP3Intel processor, AMD board. Sockets must match exactly.
CPU limit exceeded: motherboard supports maximum 1 CPUsYou are adding a second processor to a single-socket board.
… is not a CPU generation this motherboard supportsThe socket fits but the generation does not. One socket can span several generations — LGA2011-3, LGA3647, SP3 and AM4 all do — and a mismatched pair will not boot.
Incompatible CPU pairingTwo different processor models in one machine. See the note below.
SFP type QSFP+ not compatible with NIC port type SFP+The transceiver does not fit that port — different physical formats.
Storage form factor (2.5-inch) not supported by caddyThe drive tray is for a different drive size.
A matching socket is not enough for two CPUs

Multi-socket machines need identical processor models. Two CPUs can share a socket type and still be rejected — the system says so explicitly: "Multi-socket configurations require the same CPU model — a matching socket is not sufficient." This catches people out regularly.

Warnings worth reading

MessageWhat to do
ECC memory used with non-ECC motherboardThe RAM works but error correction is disabled. Fine for a lab machine, usually wrong for production.
M.2/U.2 storage does not require caddyYou have added a tray that is not needed — these drives connect directly.
NIC compatibility check skipped — specifications pendingThe catalogue entry for that card is incomplete, so it could not be checked. Verify by hand.

Why a part was rejected

When a component is blocked, every failing rule is named — not just the first. Adding an Intel processor to a board that already had an AMD one returns three findings at once: the socket does not match, the socket count is exceeded, and the models cannot be mixed. Work through them together; fixing only the first would still leave the part rejected.

Checks get stricter as the catalogue fills in

Some rules stay quiet when the catalogue has nothing to check against — the generation rule is inert for a board with no generation data recorded. As those entries are completed, combinations that were accepted before will start being refused. That is the rule working, not a regression.

07Rack View

Rack View maps physical space. A rack records its name, its site, its floor or room, and its height in rack units, and shows how many U are used and how many remain.

Creating a rack

Give it a name, pick its location from the Locations page — it is a dropdown now, not free text — and add the floor or room. Set its height in U. The setting worth pausing over is U numbering direction: racks can be numbered top-down or bottom-up. Match what is physically labelled on the rack in the hall, or every position you record afterwards will be off.

Placing servers

Servers can be placed from the rack map, or from the Move server button on the server card itself. Unassigned servers are listed alongside the map so you can see what is waiting. Unassigning returns a server to that pool without altering its configuration.

Blade enclosures and bays

Add enclosure installs a chassis such as an FX2s at a start U, optionally with its service tag. It is drawn in the elevation as a framed box with a grid of numbered bays. Clicking an empty bay installs a server into it — there is no U to choose, because the bay decides the position. Clicking the enclosure's rail opens a dialog with the roster of what is inside, and lets you rename it, re-tag it, move it to a different start U, or remove it. A server already in a bay can be moved to another bay, or out into the rack directly.

Two servers can share a U — inside an enclosure

Four sleds in one FX2s legitimately occupy the same rack units. Overlap checking treats the enclosure as the thing occupying that space, and the servers inside it as belonging to the enclosure rather than to the rack.

Free space is calculated, not typed

Used and free U are derived from what is placed in the rack and how tall it is. Moving a rack or a server also re-stamps the location onto every component inside it. A move is checked at the moment it happens, not when it was asked for — so an approved Move Server request can still be refused if the space filled up in the meantime.

08Requests

A Request is a piece of work that moves through people — a memory upgrade, a decommission, a new build. Each follows a Request Type, which defines the ordered Steps it passes through. Requests are numbered TKT-YYYYMMDD-NNNN and carry a priority of low medium high or urgent.

Requests are open to everyone

Every signed-in user can raise a Request, and claim and complete steps on one. Only administrators approve or reject. If your role cannot see the whole queue you will land on Created by me rather than My Queue — that is the right tab for you, not an empty system.

Raising one

1
Say what should happen

The form opens with a dropdown of concrete actions rather than a blank box: add, remove or replace a part in a server; create, update or re-status a server; move a server; add, edit or relocate an inventory record. Each choice renders its own fields. For inventory records the real Add or Edit Component form is embedded directly in the request.

2
Pick the server

A searchable picker finds servers by name, location, rack or UUID, with an Any server option where the work is not tied to one. Some request types are configured not to ask about a server or components at all — a door-access request, for instance.

3
Check the title and submit

The title writes itself from your choices and is marked as such; type over it if you prefer your own. The description is optional now. On submit the Request moves to its first step and appears in the queue for whoever owns it.

Checks while you fill the form in

The form looks at real stock as you go. If nothing of the chosen model is free it says so — "We have none of these free" — and offers to raise an add-to-inventory request as a prerequisite. If the part exists but sits at a different site from the server, it offers a Hardware Handover instead, naming who is carrying the part. Only that person can confirm the arrival, and their confirmation closes the handover.

Prerequisites and frozen Requests

A Request can have children — prerequisites that must be resolved before it can proceed. While one is outstanding the parent is Frozen and shows a lock banner naming the blockers; Reject and Cancel still work on a frozen Request, only progress is held. In the list, cards carry chips for Blocked, Last attempt failed, and for #TKT-… when the Request is itself a prerequisite of another. Prerequisites can nest three deep.

A rejected prerequisite still freezes its parent

A refused blocker never counts as met. Someone has to cancel or reject the parent, or an administrator has to detach the rejected child, before the parent can move again.

Approval performs the work

On the step that carries the effect the button reads Approve & run N actions rather than complete-and-advance, and an Actions panel lists what will happen, in order. After it runs, the same panel shows what it produced — asset tag, inventory ID, server, revision, the fields that changed.

Three rules govern approval

Only an administrator or super admin can approve. The work is always performed on behalf of the person who raised the Request, not the approver. And nobody approves or rejects their own Request — "Cannot approve your own request (separation of duties)". Note also that no Request can delete anything: adding, editing, moving and re-statusing are the only things approval can do.

If execution fails, nothing is changed

A failed action rolls the whole approval back and leaves a red banner — "Approval was rolled back — nothing was changed" — with the error. The step stays active, so fix the cause and approve again. A common cause is the location gate: "This component is at X, and the server is at Y. Raise a Hardware Handover request to move the part first."

Working a step

Each step has an owner — usually a role rather than a named person, so anyone holding that role can pick it up. Claim a step to signal you are working on it, then complete it to advance the Request. A step can be skipped where it does not apply. Reject is a button on every actionable step, with a box for the reason, and it is available even on frozen Requests where Approve deliberately is not. Progress reads as steps done against total.

Lifecycle

draft→ in_progress→ completed

Two endings stop a Request early: rejected when the work is declined, and cancelled when it is withdrawn. Neither can be resumed — raise a fresh Request instead.

The activity trail on each Request gains a filter bar — search, action, user and date range — once there is more than one entry to sift.

09Request Types & Vendors

These are administrator sections. They are described here so everyone understands what the system can do, even if the pages are not available to you.

Request Types

A Request Type is a named, ordered list of Steps. For each step you set a name, a position, instructions for whoever performs it, and a default owner — normally a role. Write the instructions as if for someone who has not done the task before; they are the only guidance the person working the step receives.

A step can be marked "On approval, perform the request's work". Ticking it reveals a checklist of action types — server builds, component inventory — and that checklist is the ceiling of what anyone raising this type may ask for. A separate "What the form asks for" block decides whether the create form asks about a server and a list of components at all.

Temporary access has been retired

Approving a step no longer grants anyone permissions for a period. A Request now describes work, and approval performs that work as the requester. Old steps built on the previous model display read-only as "Legacy effect — grants temporary access. This model was retired; approving this step no longer grants anything." Access to a room or a store is still requestable — an approver opens the door and records it.

General Request cannot be changed

It is built in and cannot be renamed, archived, or deleted — only its steps edited. Build a new type rather than repurposing it.

Types can be deactivated when a process is retired, which stops new Requests choosing them while existing ones keep their steps. A type can also be deleted outright; the Requests that used it keep its name on record.

Vendors

Vendors record who supplied hardware — name, contact details, what they sell, and notes. Components link to a vendor, which is what makes "everything we bought from this supplier" answerable.

Vendor records hold sensitive data

The vendor form includes banking details. Do not screenshot or share that page outside the team.

Activity Log

The Activity Log records who did what and when — components added and removed, servers changed, roles assigned. It is the first place to look when something changed and nobody remembers changing it. It now filters by free text, by date range and by user, so you can narrow to one person on one afternoon; if a search returns nothing it says the filters matched nothing rather than that the log is empty.

The log records IP addresses

Entries include the client IP of whoever performed the action. Redact before sharing screenshots outside the team.

Access Control

Administrators can reset another user's password from the Users list. The dialog takes the new password twice plus your own password to confirm, and can generate a strong one for you. Nothing is emailed — you hand the password over yourself — and the target is signed out of every device. You cannot reset your own this way; use Change Password in the account menu. Deleting a user who has raised Requests keeps their history under a placeholder rather than erasing it.

Compute platforms

The catalogue holds known server platforms — HPE ProLiant DL360, DL380, DL325 and DL385 across several generations, Dell PowerEdge, and others. A platform is stocked as a whole box, and each version of it is a distinct SKU with its own count on the shelf. Installing one supplies the build's motherboard and chassis; those are not separately stocked parts.

11Troubleshooting

I was signed out unexpectedly

A sign-in lasts 24 hours, and closing the browser ends the session's ability to renew itself even with Remember me ticked. Sign in again — unsaved form data is lost, so save long entries as you go.

A page or button is missing

Rack View and Request Types are administrator-only. Most other buttons are not hidden from you: if you lack the permission, Add Component and Build Server stay on screen and raise a Request instead. If a row's Edit or Delete is genuinely absent, that one is a permissions matter — ask an administrator.

The model I need is not in the dropdown

The hardware catalogue does not have it yet; it must be added there first. Do not substitute a similar model — compatibility checking would then run against the wrong specification.

I cannot save a component without a location

Location is required and is chosen from the Locations page. If the site you need is not listed, it has to be created there first.

I cannot delete a component

It is installed in a server. The message names the configuration — remove it from that build first, then delete. In a bulk delete the unaffected rows still go through.

A component will not add to my build

Read every finding, not just the first. Common causes: socket mismatch, a CPU generation the board does not support, full CPU or memory slots, mixed processor models, or a transceiver that does not match the port. The fit lists tell you what would work.

I cannot remove the motherboard or chassis

They came with the compute platform and are locked to it. Change or remove the platform instead — which releases the whole build — unless a separately stocked unit of the same model exists, in which case that spare can be removed on its own.

I cannot delete a server configuration

Configurations with components still attached refuse to delete and say so — for example, "This server still has 2 components installed (1 CPU, 1 motherboard). Remove all components from the server before deleting it." Remove the components, then delete.

I finalized a server by mistake

It can be sent back to Building. The status panel on the server card lists the move if your role includes it; otherwise ask an administrator.

I can edit a server's parts but not its name

Those are two different permissions. Working on the components in a build and editing the build's own details — name, description, location, status — are granted separately.

My Request is frozen

It has an unresolved prerequisite; the lock banner names it. Resolve or cancel the child. A rejected prerequisite still counts as unresolved — an administrator has to detach it, or the parent has to be cancelled.

My approval was rolled back

An action failed part-way and everything was undone, so nothing changed. The banner carries the error and the step stays active. If the reason is that the part is at another site, raise a Hardware Handover first.

I cannot approve my own Request

That is deliberate — separation of duties. Someone else with administrator rights has to approve it.

My test build has vanished

Builds made on the Server Compatibility bench are sandboxes and do not appear in the ordinary server list. Look for it there.

The numbers look wrong after a change

Dashboard counts are derived from inventory. Refresh the page; if they still look wrong, check the Activity Log to see what actually changed.
