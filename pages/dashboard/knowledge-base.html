01Getting Started

Signing in

Enter your username and password. Tick Remember me only on your own machine — it keeps you signed in between browser sessions. On a shared workstation leave it unticked, and your session ends when the browser closes.

Sessions last 30 minutes

After thirty minutes you are signed out and returned to the login screen. The system renews your session quietly in the background, so you rarely notice — but save long forms as you go rather than leaving them open.

Forgotten password

Use the reset link on the login screen. You will be emailed a single-use link to set a new password.

What you can see

The system shows only what your role allows. A missing page or a greyed-out button is a permissions matter, not a fault — ask an administrator to review your role.

02Dashboard

The dashboard answers one question: what do we have, and how much of it is free? Each hardware type gets a tile showing total, available, in use, and failed. The sidebar repeats those totals as counters, so you can watch stock without leaving the page you are on.

Below the tiles, a recent activity strip shows the latest changes across the system.

Reading the numbers

Available is in stock and free to assign. In use is installed in a server. Failed is marked faulty and excluded when building. The three always add up to the total.

03Managing Inventory

Eleven kinds of hardware are tracked, each with its own page:

PageWhat it holds
CPUsProcessors. The socket type drives most compatibility rules.
RAMMemory modules, with ECC and registered distinctions.
StorageDrives of all form factors — 2.5-inch, 3.5-inch, M.2, U.2.
MotherboardsSystem boards. Define socket, memory slots, and PCIe layout.
Network CardsNICs, including their port types.
CaddiesDrive trays. Must match the drive form factor and the chassis.
ChassisThe enclosure, with its rack height in U.
PCIe CardsExpansion cards that consume lanes and slots.
Riser CardsAdapters that redirect PCIe slots within a chassis.
HBA CardsHost bus adapters for storage connectivity.
SFP ModulesOptical and direct-attach network transceivers.

Adding a component

1
Pick the model

Cascading dropdowns narrow from brand, to series, to model. You are choosing from the hardware catalogue, not typing freehand.

2
Identify the physical unit

Enter the serial number. An asset tag such as BDC-CPU-000128 is generated for you. The serial is what tells two identical units apart.

3
Set status and location

Status is Available, In Use, or Failed. Location is free text — a site or store room.

4
Add dates and notes

Purchase, installation, and warranty-end dates are optional but make warranty reporting useful.

The model must exist in the catalogue

Every component is checked against the catalogue before saving. If your model is not in the dropdowns it must be added there first. Do not pick the nearest match — compatibility checking would then run against the wrong specification.

Editing, deleting, and bulk actions

Rows can be edited or deleted individually, and several rows can be selected for a bulk update or delete — useful when a shipment arrives or a batch is retired.

Components in use cannot be deleted outright

Remove the unit from its server configuration first. Otherwise a server record would refer to hardware that no longer exists.

04Building a Server

The Server Builder assembles a configuration from units already in inventory, checking at each step that the parts fit together.

1
Start the configuration

Name it, optionally add a description and location. It opens as a draft.

2
Choose the motherboard first

Nearly every later rule derives from the board — its socket, memory slots, and PCIe layout. Picking it first lets the builder filter everything else for you.

3
Add components, guided by the fit lists

For each type the builder shows what fits and what does not, with a reason on every entry — and separates parts that fit and are in stock from those already in use elsewhere.

4
Validate

Validation lists missing required components and shows how much of each resource you have consumed.

5
Finalise and place it

A finalised configuration can be assigned to a rack and moved through its deployment states.

Six components are required

A configuration is not complete until it has all of: chassis, motherboard, CPU, RAM, storage, and a network card.

The resource budget

Validation shows where you stand against the board's limits. A single-socket board with a 128-lane CPU reports something like:

ResourceMaxUsedFree
CPU sockets110
Memory slots808
Memory capacity (GB)204802048
PCIe lanes1280128
PCIe slots ×16505

PCIe lanes are attributed to their source, so you can see the budget comes from the CPU rather than the board.

Trying things out safely

The Server Compatibility page is a bench for experimenting. Builds made there are sandboxes and never reserve real stock, so you can test a combination without taking parts out of circulation.

Sandbox builds are kept separate

A sandbox build does not appear in the ordinary server list — it belongs to the Server Compatibility bench. If a test build seems to have vanished, that is why; it has not been deleted.

05Understanding Compatibility

Every check returns findings in three buckets. Which bucket you are looking at tells you what to do next.

Issues

Hard stops. The combination will not work and cannot be saved.

Warnings

It will work, but something is compromised or unnecessary.

Recommendations

How to resolve it — often naming the parts that would fit.

Issues you will actually meet

MessageWhat it means
CPU socket LGA3647 incompatible with motherboard socket SP3Intel processor, AMD board. Sockets must match exactly.
CPU limit exceeded: motherboard supports maximum 1 CPUsYou are adding a second processor to a single-socket board.
Incompatible CPU pairingTwo different processor models in one machine. See the note below.
SFP type QSFP+ not compatible with NIC port type SFP+The transceiver does not fit that port — different physical formats.
Storage form factor (2.5-inch) not supported by caddyThe drive tray is for a different drive size.
A matching socket is not enough for two CPUs

Multi-socket machines need identical processor models. Two CPUs can share a socket type and still be rejected — the system says so explicitly: "Multi-socket configurations require the same CPU model — a matching socket is not sufficient." This catches people out regularly.

Warnings worth reading

MessageWhat to do
ECC memory used with non-ECC motherboardThe RAM works but error correction is disabled. Fine for a lab machine, usually wrong for production.
M.2/U.2 storage does not require caddyYou have added a tray that is not needed — these drives connect directly.
NIC compatibility check skipped — specifications pendingThe catalogue entry for that card is incomplete, so it could not be checked. Verify by hand.

Why a part was rejected

When a component is blocked, every failing rule is named — not just the first. Adding an Intel processor to a board that already had an AMD one returns three findings at once: the socket does not match, the socket count is exceeded, and the models cannot be mixed. Work through them together; fixing only the first would still leave the part rejected.

06Rack View

Rack View maps physical space. A rack records its name, site, and height in rack units, and shows how many U are used and how many remain.

Creating a rack

Give it a name and location and set its height in U. The setting worth pausing over is U numbering direction — racks can be numbered top-down or bottom-up. Match what is physically labelled on the rack in the hall, or every position you record afterwards will be off.

Placing servers

Finalised configurations can be assigned to a rack at a starting U position. Unassigned servers are listed alongside the rack map so you can see what is waiting to be placed. Unassigning returns a server to that pool without altering its configuration.

Free space is calculated, not typed

Used and free U are derived from the servers placed in the rack and the height of their chassis. You do not maintain them by hand.

07Requests

A Request is a piece of work that moves through people — a memory upgrade, a decommission, a new build. Each follows a Request Type, which defines the ordered Steps it passes through.

Requests are numbered TKT-YYYYMMDD-NNNN and carry a priority of low medium high or urgent.

General Request

The built-in type, with three steps:

#StepWhat happens
1ApprovalReview the request and approve it to proceed.
2ExecutionCarry out the approved work.
3DeploymentDeploy or finalise, and close the request.

Working a step

Each step has an owner — usually a role rather than a named person, so anyone holding that role can pick it up. Claim a step to signal you are working on it, then complete it to advance the Request. A step can be skipped where it does not apply, or rejected, which sends the Request back.

Lifecycle

draft→ in_progress→ completed

Two endings stop a Request early: rejected when the work is declined, and cancelled when it is withdrawn. Neither can be resumed — raise a fresh Request instead.

Access

Requests and Request Types are available to administrators. If you cannot see them in the sidebar, that is why.

08Request Types & Vendors

These are administrator sections. They are described here so everyone understands what the system can do, even if the pages are not available to you.

Request Types

A Request Type is a named, ordered list of Steps. For each step you set a name, a position, instructions for whoever performs it, and a default owner — normally a role. Write the instructions as if for someone who has not done the task before; they are the only guidance the person working the step receives.

General Request cannot be changed

It is built in and cannot be renamed, archived, or deleted — only its steps edited. Build a new type rather than repurposing it.

Types can be deactivated when a process is retired. Requests already using a type keep their steps; deactivating only stops new Requests from choosing it.

Vendors

Vendors record who supplied hardware — name, contact details, what they sell, and notes. Components link to a vendor, which is what makes "everything we bought from this supplier" answerable.

Vendor records hold sensitive data

The vendor form includes banking details. Do not screenshot or share that page outside the team.

Activity Log

The Activity Log records who did what and when — components added and removed, servers changed, roles assigned. It is the first place to look when something changed and nobody remembers changing it.

The log records IP addresses

Entries include the client IP of whoever performed the action. Redact before sharing screenshots outside the team.

Glossary

TermMeaning
URack unit — 1.75 inches of vertical rack space. A 2U server occupies two.
SocketThe physical processor mount. SP3 is AMD; LGA3647 and LGA2011-3 are Intel. Not interchangeable.
ECCError-correcting memory. Needs board support, otherwise correction is simply disabled.
PCIe laneThe bandwidth budget for expansion cards, supplied mostly by the CPU. Cards consume lanes; you can run out.
CaddyThe tray holding a drive in a chassis. Must match the drive size and the chassis.
SFP / QSFP+Pluggable network transceiver formats. QSFP+ is larger and will not fit an SFP+ port.
HBAHost bus adapter — a card connecting storage devices to the system.
Asset tagThe generated identifier for a physical unit, such as BDC-CPU-000128.

10Troubleshooting

I was signed out unexpectedly

Sessions last thirty minutes. Sign in again — unsaved form data is lost, so save long entries as you go.

A page or button is missing

Your role does not include it. Rack View, Requests, Request Types, and Vendors are restricted to administrators. Ask an administrator to review your role rather than working around it.

The model I need is not in the dropdown

The hardware catalogue does not have it yet; it must be added there first. Do not substitute a similar model — compatibility checking would then run against the wrong specification.

I cannot delete a server configuration

Configurations with components still attached refuse to delete and say so — for example, "This server still has 2 components installed (1 CPU, 1 motherboard). Remove all components from the server before deleting it." Remove the components, then delete.

A component will not add to my build

Read every finding, not just the first. Common causes: socket mismatch, full CPU or memory slots, mixed processor models, or a transceiver that does not match the port. The fit lists tell you what would work.

My test build has vanished

Builds made on the Server Compatibility bench are sandboxes and do not appear in the ordinary server list. Look for it there.

The numbers look wrong after a change

Dashboard counts are derived from inventory. Refresh the page; if they still look wrong, check the Activity Log to see what actually changed.
